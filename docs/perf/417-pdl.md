# Programmatic dependent launch (#417)

`[runtime] pdl = true` launches every kernel through `cuLaunchKernelEx` with the programmatic stream serialization attribute and prefixes each kernel with `griddepcontrol.wait` and `griddepcontrol.launch_dependents` (cc 90 and up). Default is off.

Measured on the desktop RTX PRO 6000 (GPU1, user's window), bench single stream, prompt 128, 256 new tokens, alternating A/B, 3 rounds, under `flock /tmp/gpu27.lock`:

| model | pdl off tok/s | pdl on tok/s | change |
|---|---|---|---|
| Qwen3-0.6B bf16 | 855.2, 855.3, 855.1 | 892.4, 893.7, 893.2 | +4.4% |
| Qwen3.8-27B NVFP4 (rounds 1-2) | 58.9, 58.9 | 57.0, 56.3 | -3.5% |

Small models are gap bound and gain. The 27B loses: early `launch_dependents` lets the next kernel occupy SMs while the current one still runs. Rule from the issue: keep PDL only at +3%, so it stays opt-in per model spec (small models).

Not run: Spark numbers, phi3-mini, llama.cpp ratio, nsys fusion survey.

Tests (`tests/pdl.rs`, ignored, GPU): logits bit identical and greedy equal with pdl on and off on ten tiny fixtures and Qwen3-0.6B; graph and eager batch decode agree with pdl on and off.
